# 冷库需量账单峰值核账（单表单期）

Flask + SQLite 的核账页：上传整分钟累计用电 CSV（整数 Wh，电表不回卷），
核对账单所报 15 分钟峰值时段是否存在一种整数分钟用电分配，使该时段**恰好**
达到账单峰值、其余不重叠的 15 分钟时段均**不超过**该值。

## 模型与算法（不逐分钟铺开缺读段，也不逐 Wh 分配）

- 时间轴只按「相邻实读之间的段」×「15 分钟窗」的**交集切块**，块数
  O(读数数 + 窗数)，与缺读段内分钟数、Wh 数无关。31 天仅首尾两读数时
  块数 = 2976（窗数），而不是 44640 分钟。
- 每块是整数变量 x∈[L,H]：`L=max(0, d-(n-k)U)`、`H=min(kU, d)`，
  其中 n 为段内分钟数、k 为块内分钟数、d 为段固定电量、U 为每分钟上限。
- 段→窗构成二部流：S→段固定为段电量 d，块边带 [L,H] 下界，窗→T 带界。
  区间矩阵全幺模，整数解与 LP 解等价。
- **可行判定**：带下界可行流（Dinic + 超源/超汇）。
- **所报窗可达区间**：对目标值二分，分别求最小/最大可达电量。
- **最小越限方案**：最小费用流（势 + Dijkstra），其它窗的守限部分费用 0、
  越限部分费用 1/Wh，得到最小越限总量与被迫越限的窗。

## 三种结论

| status | 含义 |
| --- | --- |
| `feasible` | 存在分配：所报窗恰为峰值，其余窗均不超过；列出全期各窗电量 |
| `target_unreachable` | 所报时段本身达不到该值，附其可达区间 [min, max] |
| `others_breach` | 所报窗可达，但其余时段无法同时守住上限，附最小越限量与越限窗 |

## 数据规则

- 账期取首末读数，两端必须对齐 15 分钟边界，最长 31 天。
- 账期内可补传，**同刻覆盖**；合并后若回卷或超过每分钟上限导致实读无解，
  **整批拒绝**并指出冲突的相邻读数，库内数据与结论不变。
- **补传即重算**：补传成功后自动按库内现行参数（每分钟上限、账单峰值、
  所报时段）重新核对。读数与新的当前结论在**同一事务**内生效；
  账单核不过（`target_unreachable` / `others_breach`）也会保存新结论，
  网页与 CSV 立即同步，不会再沿用旧结论。现行参数尚未齐备时只合并读数、
  不触发重算。
- `initial` 结论只在本账期首次成功手工核对时写一次并永久保留；
  补传重算只更新 `current`，从不覆盖初核。
- 手工核对失败（参数非法或实读无解）不覆盖任何现有数据与结论。

## 交错提交与并发保证

- 所有输入校验与 solver 重计算都在写事务**之外**完成，提交只走一个很短的
  `BEGIN IMMEDIATE` 事务。因此即使求解耗时较长，期间仍可正常查看网页、
  下载已有 CSV、清空账期。
- 每次查看/下载都在**同一只读快照事务**里取齐读数、参数与结论，
  不会把两次提交的数据拼在一起。
- 写事务内复核账期代号（epoch）与读数/参数指纹：
  - 读数冲突、参数无效、求解失败或写入失败 → 本次改动整体不生效，无半成品；
  - 两批补传、或补传与改参数交错，若各自有效且合并后仍有效 →
    服务端带最新状态重新校验重算（乐观重试），两次改动都生效；
  - 合并后变为无效（回卷/超上限/无解）→ 后到的一笔整笔拒绝。
- 清空账期会令 epoch 加 1。清空前已受理、但尚未提交的补传或核对，
  其旧 epoch 立即失效，**不会回写新账期**——即使新账期录入了完全相同的读数。
- SQLite 以 WAL 模式打开并配置 `busy_timeout`，配合 gunicorn 多 worker
  实现"读不阻塞写、写不阻塞读、写与写串行"。

## CSV 格式

```
timestamp,reading
2026-11-01 00:00,0
2026-11-01 00:15,30
```

## 启动

### Docker Compose（推荐）

```bash
docker compose up -d --build
# 打开 http://localhost:8000
```

SQLite 数据持久化在命名卷 `meter-data`（容器内 `/data/meter.db`）。

### 本地直接运行

```bash
pip install -r requirements.txt
python wsgi.py            # 开发服务器，:8000
# 或
gunicorn --bind 0.0.0.0:8000 wsgi:app
```
